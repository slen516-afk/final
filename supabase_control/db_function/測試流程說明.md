# db_writes 測試流程說明

本說明書引導你依序跑完「腳本測試」與「Flask API 測試」，確認 `db_writes` 的寫入邏輯與連線正常。

---

## 一、前置準備

### 1.1 環境變數（.env）

- 在 **`supabase_control/`** 或 **`supabase_control/Erd/`** 其中一個位置放 `.env`。
- 內容需包含（變數名不可改）：
  ```env
  SUPABASE_URL=你的 Supabase 專案 URL
  SUPABASE_SERVICE_ROLE_KEY=你的 service_role key
  ```
- 若只有 `Erd/.env_example`，可複製為 `.env` 再填入實際值。

### 1.2 Python 套件

- 本模組依賴：`supabase`、`python-dotenv`（連線用）。
- 跑 **Flask 範例** 時需額外安裝：`flask`。
  ```bash
  pip install supabase python-dotenv flask
  ```

### 1.3 資料庫

- Supabase 專案中需已建立 **`upload_event`** 表（本測試以 `create_upload_event` 為例）。
- 若表尚未建立，請先依專案 ERD 在 Supabase 建立對應表結構。

## 二、測試一：腳本直接寫入（不經 Flask）

目的：確認「連線 + 呼叫 db_writes 函數 + 寫入 DB」沒問題。

### 步驟

1. 開啟終端機，進入專案目錄。
2. 任選一種方式執行腳本：

   **方式 A（建議）：從 supabase_control 執行**
   ```bash
   cd supabase_control
   python db_function/test_db_writes_manual.py
   ```

   **方式 B：從專案根目錄執行**
   ```bash
   # Windows PowerShell
   $env:PYTHONPATH = "supabase_control"
   python supabase_control/db_function/test_db_writes_manual.py

   # Windows CMD
   set PYTHONPATH=supabase_control
   python supabase_control/db_function/test_db_writes_manual.py
   ```

3. 觀察輸出。

### 預期結果（成功）

- 終端會先出現 Supabase 連線成功訊息。
- 接著出現類似：
  ```
  ==================================================
  測試 db_writes：create_upload_event
  ==================================================
  OK 寫入成功
  回傳資料: {'event_id': ..., 'user_id': 1, 'file_name': 'test_resume.pdf', ...}
  ```

### 常見錯誤與處理

| 錯誤訊息 / 狀況 | 可能原因 | 處理方式 |
|-----------------|----------|----------|
| 找不到 .env / FileNotFoundError | .env 不在上述路徑 | 在 `supabase_control/` 或 `supabase_control/Erd/` 建立 `.env` 並填好變數 |
| 無法讀取 SUPABASE_URL / SUPABASE_SERVICE_ROLE_KEY | .env 裡變數名錯或為空 | 確認變數名為 `SUPABASE_URL`、`SUPABASE_SERVICE_ROLE_KEY`，且都有值 |
| 寫入失敗 / RuntimeError | 權限、表不存在、或欄位不符 | 到 Supabase Dashboard 檢查是否有 `upload_event` 表，以及 RLS/權限是否允許寫入 |
| user_id 必須為整數 | 腳本內 user_id 型別錯誤 | 腳本預設為 1；若你的 DB 沒有 user_id=1，可改 `test_db_writes_manual.py` 裡的 `user_id` 為已存在的使用者 ID |

## 三、測試二：透過 Flask API 寫入

目的：確認「後端收到請求 → 呼叫 db_writes → 回傳結果」的流程與你之後併入後端時一致。

### 步驟

1. **啟動 Flask 範例**
   ```bash
   cd supabase_control
   python db_function/flask_example.py
   ```
   看到類似 `Flask 範例：POST http://127.0.0.1:5000/api/upload-event` 即表示已啟動。

2. **發送測試請求**

   **用 curl（終端機）：**
   ```bash
   curl -X POST http://127.0.0.1:5000/api/upload-event ^
     -H "Content-Type: application/json" ^
     -d "{\"user_id\": 1, \"file_name\": \"my_resume.pdf\", \"file_path\": \"uploads/1/my_resume.pdf\"}"
   ```
   （Linux / macOS 把 `^` 改成 `\` 換行即可。）

   **用 Postman：**
   - Method：**POST**
   - URL：`http://127.0.0.1:5000/api/upload-event`
   - Headers：`Content-Type: application/json`
   - Body：選 **raw**、**JSON**，內容例如：
     ```json
     {
       "user_id": 1,
       "file_name": "my_resume.pdf",
       "file_path": "uploads/1/my_resume.pdf"
     }
     ```
   可選加 `"upload_type": "resume"`。

3. 觀察回應。

### 預期結果（成功）

- HTTP 狀態碼 **201**。
- 回應為 JSON，例如：
  ```json
  {
    "ok": true,
    "data": {
      "event_id": ...,
      "user_id": 1,
      "file_name": "my_resume.pdf",
      "file_path": "uploads/1/my_resume.pdf",
      "uploaded_at": "..."
    }
  }
  ```

### 常見錯誤與處理

| 狀況 | 可能原因 | 處理方式 |
|------|----------|----------|
| 400 需要 JSON body | 未送 body 或 Content-Type 不是 application/json | 確認 Body 為 JSON 且 Header 設好 |
| 400 必填: user_id, file_name, file_path | 少欄位或 key 打錯 | 確認 JSON 裡有這三個欄位且名稱正確 |
| 500 / RuntimeError | 同「測試一」的寫入失敗 | 檢查 .env、Supabase 表與權限 |

## 四、如何確認資料有寫進資料庫

1. 登入 [Supabase Dashboard](https://app.supabase.com)。
2. 選你的專案 → **Table Editor**。
3. 開啟 **`upload_event`** 表。
4. 應能看到剛才腳本或 API 寫入的筆數（例如 `user_id=1`、`file_name=test_resume.pdf` 或 `my_resume.pdf`）。

---

## 五、總結

| 項目 | 檔案 | 通過條件 |
|------|------|----------|
| 測試一 | `test_db_writes_manual.py` | 終端顯示「OK 寫入成功」且回傳一筆資料 |
| 測試二 | `flask_example.py` + POST 請求 | 收到 201 且 `ok: true`、`data` 內有 `event_id` 等 |
| 可選 | Supabase Table Editor | `upload_event` 表中有對應新資料 |

兩項都通過即代表「連線 + db_writes 邏輯 + Flask 接法」正常，其餘函數（問卷、個人檔案、履歷等）可依相同方式在後端接上並測試。
