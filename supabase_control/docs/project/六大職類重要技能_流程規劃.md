# 六大職類重要技能表列 — 流程規劃

## 目標

針對六大職類 (A–F)，各產出「相對重要的前 6 項技能」，供前端顯示。

---

## 既有資料是否夠用？

### 會用到的資料（都在 DB）

| 來源 | 用途 |
|------|------|
| **job_posting** | `job_id`, `role_type`(A–F), `role_name`, `is_labeled` — 已貼標的職缺才能納入統計 |
| **job_skill_requirement** | `job_id`, `skill_id`, `importance` — 職缺–技能關聯（由 `job_skill_requirement.py` 寫入） |
| **skill_master** | `skill_id`, `skill_name` — 技能顯示名稱 |

### 既有 CSV 的角色

| 檔案 | 用途 | 本功能是否需要 |
|------|------|----------------|
| **skill_master_rows.csv** | 當初寫入/備份 `skill_master` 的資料 | **不需要** — 技能名稱以 DB 的 `skill_master` 為準 |
| **unmatched_skills.csv** | 職缺中出現但未對到 `skill_master` 的技能，供後續補表 | **不需要** — 本功能只統計「已對到 skill_id」的關聯 |

結論：**不需要再讀這兩個 CSV**，直接從 Supabase 查 `job_posting` + `job_skill_requirement` + `skill_master` 即可。

---

## 資料流與提取邏輯

```
已貼標職缺 (job_posting.is_labeled=true, role_type 有值)
    ↓
職缺–技能關聯 (job_skill_requirement)
    ↓
依 (role_type, skill_id) 彙總出現次數
    ↓
每個 role_type 取出現次數最高的前 6 個 skill_id
    ↓
join skill_master 取得 skill_name
    ↓
輸出：{ "A": [技能1, ... 共6個], "B": [...], ... }
```

### 重要假設

- **「重要」的定義**：在該職類中，**出現於多少筆已貼標職缺**（出現越多次越重要）。
- 僅統計 **已貼標** 且 **有 role_type** 的職缺；目前約 6x% 已貼標，數字會隨貼標進度增加而變動。
- 若某職類已貼標職缺數很少，前 6 名可能不足 6 筆，如實輸出即可。

## 實作方式建議

### 方案一：後端腳本產出 JSON/CSV，前端讀靜態或透過 API

1. **腳本**（已提供：`scripts/jobs/top_skills_by_role_type.py`）
   - 從 DB 查：已貼標職缺 × job_skill_requirement × skill_master。
   - 依 `role_type` 彙總每個 `skill_id` 的職缺數，取每職類 top 6。
   - 產出：
     - **JSON**：給前端或 API 直接回傳（例如 `data/role_type_top_skills.json`）。
     - 可選：**CSV**（例如 `data/role_type_top_skills.csv`）方便檢視或滙入。

2. **更新時機**：手動執行、或排程（cron）在貼標/技能資料更新後跑一次。

3. **前端**：呼叫後端 API 取得該 JSON，或若你們是靜態部署則讀打包進前端的 JSON。

### 方案二：Supabase 資料庫 View + 前端直接查

1. 在 Supabase 建立 **View**（或 RPC）：
   - 底層邏輯同上：已貼標職缺 JOIN job_skill_requirement，GROUP BY role_type, skill_id，再取每 role_type 前 6 名並 join skill_master。
2. 前端：對該 View 或 RPC 做 `select`，依 `role_type` 分組顯示。

優點：資料即時；缺點：需要寫 SQL View/RPC，且若資料量大要做效能考量（可再做成 materialized view 或定時更新的表）。

### 方案三：預先寫入「職類–前 6 技能」表，前端只查一張表

1. 新增表例如 **role_type_top_skills**（欄位：`role_type`, `skill_id`, `skill_name`, `rank`, `job_count`）。
2. 用同一套彙總邏輯的腳本（或 SQL）**定時更新**該表（例如每日或每次貼標批次後）。
3. 前端：`select * from role_type_top_skills where role_type = 'A' order by rank` 等，簡單且快。

---

## 建議流程總結

1. **短期**：用腳本 `top_skills_by_role_type.py` 從現有 DB 產出 **JSON**（及可選 CSV），前端先對接此 JSON（或後端 API 回傳此 JSON）。
2. **中期**：若希望資料即時、或不想手動跑腳本，可改為 **Supabase View/RPC** 或 **role_type_top_skills 表 + 定時更新腳本**，前端改查 DB。
3. **既有 CSV**：`skill_master_rows.csv` / `unmatched_skills.csv` 本功能**不需使用**；技能名稱與關聯一律以 DB 為準。
