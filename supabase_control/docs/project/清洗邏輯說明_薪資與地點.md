## 一、薪資（clean_salary）— 「比例怎麼補回來」

### 1. 目的

原始 `salary` 欄有的是「待遇面議」、有的是「50,000~80,000」、有的是「月薪 60000」等，無法直接比較或篩選。  
清洗後統一輸出 **salary_min / salary_max**，讓每一筆都有可比較的數字，**「有薪資區間」比例**就從約 41% 提升到 100%。

### 2. 補回邏輯（優先順序）

| 原始內容 | 處理方式 | 輸出 (min, max) |
|----------|----------|------------------|
| 空值 / 無法解析 | 不回填，維持空 | (None, None)；寫入 DB 時再轉成 0 |
| **「面議」或「面谈」** | **統一給一個代表值** | **(40,000, 40,000)** |
| 區間格式（數字~數字） | 用正則抓兩個數字，取 min/max | 例如 "50,000~80,000" → (50000, 80000) |
| 「月薪 60000」 | 單一數字 | (60000, 60000) |
| 「X元」（單一數字+元） | 當作下限，上限給很大 | (X, 999999) |

也就是說：  
- **「比例補回來」主要來自「面議 → 40,000」**：原本沒有數字區間的「待遇面議」被統一成 (40000, 40000)，所以這批筆數從「無區間」變成「有區間」，整體「有薪資區間」比例就拉高。  
- 其他有寫數字的，只是**格式統一**成 (min, max)，沒有「補值」的問題。

### 3. 程式碼位置與片段

在 **clear.ipynb 階段二** 的 `clean_salary`：

## 二、地點（standardize_location）— 「大家寫法差異大怎麼弄整齊」

### 1. 問題

原始只有一欄 **location**，寫法很多樣，例如：

- 「台北市信義區」「新北市板橋區」
- 「台北市」「新竹市東區」
- 「台中市西屯區台灣大道」
- 有的帶路名、有的只有縣市+區、有的縣市名重複（如「新竹市新竹市東區」）

要能篩選「縣市」「行政區」，就要拆成 **full_address / city / district** 並統一格式。

### 2. 整齊的方式（三步）

- **Step 1：只收有值的部分，拼成一個字串**  
  函數簽名是 `standardize_location(city, district, location)`。  
  CSV 只有 `location`，所以實際呼叫是：
  ```python
  standardize_location(None, None, r.get("location"))
  ```
  把 `city, district, location` 裡非空的部分依序拼成 **full_address**（例如就是那一大串「台北市信義區…」）。

- **Step 2：用「縣市名」從頭匹配，拆出 city**  
  預先定義 **CITIES** 列表（台北市、新北市、桃園市、…、連江縣等），用 `full.startswith(c)` 找到第一個匹配的縣市，當作 **city**，剩下字串當 **rest**（例如「信義區…」）。

- **Step 3：從 rest 拆出 district（區/鄉/鎮/市）**  
  - **新竹市、嘉義市**：只用一組 **VALID_DISTRICTS**（東區、北區、香山區、西區）從 rest 開頭匹配，避免把「科學園區」等當成行政區。  
  - **其他縣市**：用正則 **DISTRICT_SUFFIX**（`^(.+?[區鄉鎮市])`）抓「到第一個區/鄉/鎮/市」當 district；若沒抓到，再用另一個正則 `^([^\d路街段巷弄號]+?[區鄉鎮市])` 試一次。  
  - 有 **GARDEN_BLACKLIST**（工業園區、科學園區、園區、太空中心）：這些詞不會被當成 district，避免誤拆。

- **重複縣市名**：若 rest 開頭又出現同一個縣市名（如「新竹市新竹市東區」），會先去掉重複的那一段再拆 district。

結果就是：  
- **full_address**：原始字串整理後的一整段（可保留路名等）。  
- **city**：一定是 CITIES 裡的一個（台北市、新北市、…）。  
- **district**：一個區/鄉/鎮/市名稱，或 None（沒拆到就不填）。

這樣不論大家寫「台北市信義區」「台北市 信義區」或「台北市信義區忠孝東路…」，都會被整成同一套 **city = 台北市、district = 信義區**，寫法就整齊了。

### 3. 程式碼位置與片段

在 **clear.ipynb 階段二**：

- **CITIES** 與 **VALID_DISTRICTS / GARDEN_BLACKLIST** 的定義。
- **standardize_location(city, district, location)** 回傳 `(full_address, city, district)`。

職缺表套用方式（階段四）：

```python
loc_out = df_jobs.apply(lambda r: standardize_location(None, None, r.get("location")), axis=1)
df_jobs["full_address"] = [x[0] for x in loc_out]
df_jobs["city"] = [x[1] for x in loc_out]
df_jobs["district"] = [x[2] for x in loc_out]
```

## 三、對 PPT / 口頭說明可怎麼講

- **薪資**：  
  「原始很多是『待遇面議』、格式也不一。我們把面議統一給一個可比較的代表值（4 萬），區間或月薪用正則拆成 salary_min / salary_max，所以清洗後每一筆都有數字區間，『有薪資區間』比例從約 41% 變成 100%。」

- **地點**：  
  「原始只有一欄 location，大家寫法差異很大。我們用預先定義的縣市與區鄉鎮市規則，從字串開頭匹配縣市、再拆出行政區，排除工業園區等非行政區，輸出 full_address、city、district 三欄，後續篩選與分析就都用同一套格式。」

這樣就對應到你當初「薪資比例補回來」與「地點弄整齊」的邏輯。

## 四、公司產業分類（industry）— 當初怎麼做的

### 1. 整體流程

產業是**以公司為單位**決定的（先依 `company_name` 分組、彙總該公司底下所有職缺的 `job_category`，再決定這家公司屬於哪一個產業）。  
決定順序是：

1. **先看公司名稱**：用 `extract_industry(company_name)`，依關鍵字分層匹配。
2. **公司名稱沒匹配到**：用 **職缺類別 fallback**：`infer_industry_from_job_category(該公司彙總的 job_category)`。
3. **還是沒有**：標成 **「未分類」**。

也就是：**公司名稱 → job_category 彙總 fallback → 未分類**。

### 2. 公司名稱怎麼推產業（extract_industry）

- 先把公司名稱做 **clean_company_name**（去掉「股份有限公司」「有限公司」「集團」「分公司」「財團法人」等後綴），用剩下來的名字做關鍵字匹配。
- 關鍵字分 **三層優先級**（先匹配到的先贏）：
  - **Tier 1 特定領域**：  
    製造業（半導體製造、製程、產線、封裝測試、晶圓、fab、光電、台積電等）、  
    醫療（醫療器材、醫藥、生技、藥廠、醫檢、診所、醫院、醫材、生醫、製藥、藥業等）、  
    金融業（銀行、保險、證券、投信、金控、金融、控股、資產管理）。  
    - 特例：**「人力銀行」** 不會被判成金融業（關鍵字裡排除「銀行」在人力銀行的情況）。
  - **Tier 2 複合領域**：  
    資訊科技（軟體、網路服務、雲端、ai應用、資安、系統整合）、  
    製造業（材料、精密、機械）。
  - **Tier 3 通用**：  
    資訊科技（科技、資訊、數位）、  
    服務業（服務）。
- 若三層都沒匹配到，但有傳入 **job_category**，就改呼叫 **infer_industry_from_job_category(job_category)** 當 fallback；沒有就回傳 None（最後在 _resolve_industry 會變成「未分類」）。

### 3. 職缺類別 fallback（infer_industry_from_job_category）

當公司名稱推不出產業時，用該公司**彙總後的 job_category**（同一公司多筆職缺的 job_category 用 ` | ` 串起來）再推一次。  
比對的是**職缺類別字串**裡是否出現下列關鍵字（先匹配到先贏）：

- **資訊科技**：軟體、程式、系統分析、internet、mis、韌體、資料庫、資安、演算法、dba、bios、全端、後端、前端、資料科學、大數據、雲端、devops、sre、嵌入式、網管、qa 等。
- **製造業**：製造、產線、設備、製程、機構工程、半導體、光電、pcb、smt、品保、倉管、生產、焊接、cnc、品管、qc、qe、ie、me、廠務、生產線、作業員 等。
- **金融業**：金融、銀行、保險、證券、理財、風控、精算、授信、櫃員。
- **醫療**：醫護、護理、藥師、醫檢、醫事、醫師、護理師、醫檢師、醫療器材、醫學工程、臨床、復健。
- **行銷**：行銷、廣告、媒體、電商、社群、文案、企劃、數位行銷。
- **商業**：人資、會計、財務、審計、業務、客服、採購、行政、總務、秘書、法務、顧問。
- **設計**：設計、ui、ux、平面、工業設計、視覺。
- **教育**：教師、講師、教練、補習、教材、教學。

都沒匹配到就回傳 None → 該公司最後會被標成「未分類」。

### 4. 程式碼位置

- **階段二**：`clean_company_name`、`PRIORITY_LAYERS`、`extract_industry`、`infer_industry_from_job_category`。
- **階段三**：先 `groupby("company_name")` 彙總 `job_category`（`_agg_job_cats`），再對每一家 `_resolve_industry`：  
  `extract_industry(company_name)` → 若 None 則 `infer_industry_from_job_category(job_categories)` → 若仍 None 則 `"未分類"`。

結果約 **5,196 / 5,668 家** 有明確產業（非未分類），其餘為「未分類」。
